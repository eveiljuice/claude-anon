# claude anon — «инкогнито-режим» для Claude Code

- Дата: 2026-10-07 (обновлено 2026-10-08 — чистый контекст mid-session, v0.2.0;
  2026-10-10 — публикуется как плагин, лаунчер-разделы удалены из этой копии)
- Статус: спека реализована (v0.1.0 — инкогнито-базис, v0.2.0 — чистый контекст)
- Платформа: Windows 11, Claude Code (терминал; где возможно — desktop surface)

## 1. Цель

Claude anon — режим Claude Code «как приватное окно браузера»: Claude стартует или
работает без знания о пользователе, не оставляет следов на диске, глушит телеметрию
и **виден глазом** — клиент визуально перекрашивается в фиолетовый, пока
режим активен. Официальное название режима: **claude anon**.

Список отключенного (утверждён пользователем):

1. **Чистый контекст** —Claude не видит auto-memory/MEMORY.md, CLAUDE.md, историю подсказок.
2. **Не сохранять сессию** — transcript не остаётся на диске.
3. **Не писать память** — записи в память блокируются.
4. **Без телеметрии** — DISABLE_TELEMETRY и связанные, error-reporting тоже.

Визуальная часть (утверждена пользователем):

- фиолетовая полоса (band) вплотную над полем ввода, с собственным фиолетовым маскотом;
- фиолетовый лейбл **claude anon** в футере у индикатора режимов (рядом с `focus`,
  `memory paused`);
- заголовок вкладки/окна терминала — **Claude Code Anon**, пока режим активен.

## 2. Активация: команда `/anon` — режим внутри обычной сессии

Через мод (см. 3). Контекст первого хода (claudeMd, userEmail, attachedProject,
gitStatus), собранный к моменту включения, в беседе уже есть — его не «раз-инкогнитить»,
и полоса честно показывает `context loaded before going anon` (уточнение спеки
2026-10-08: mid-session-режим теперь всё же лечится частично — всё, что движок собрал бы
после включения, не уходит; см. 3.2). Включённый до первого сообщения `/anon` даёт
полностью чистый первый ход: вырезка блоков + пустые instructionFiles + срезанные
секции памяти + заглушенные памятные вложения.

## 3. Компонент: мод `claude-anon`

Hooks-модуль (не shell-hooks, а function-hooks движка). Источник:
`mod/claude-anon/` этого репозитория.

Файлы: `.claude-plugin/plugin.json`, `hooks/hooks.json` (`{ "modules": ["./register.tsx"] }`),
`hooks/register.tsx`, `types/index.d.ts` (контракт `$.state`), тесты `*.test.ts`.

### 3.1 Состояние

- `$.state` (сессия): `{ anonOn: boolean, launcherMode: boolean, restoredTitle: string | null,
  notice: string | null, contextUnloaded: boolean | null }` — `contextUnloaded` означает
  «вырезка контекста первого хода состоялась в этой беседе» (полоса честно обещает
  `memory unloaded`); на `/anon off` снимается — та же беседа контекст уже несёт.
- `$.store` (межсессионное): `anon-manifest: Record<sessionId, { transcriptPath: string; sessionDir: string }>` —
  список сессий, у которых transcript и каталог сессии подлежат удалению; источник сирот
  после крэша (в записи хранятся абсолютные пути, снятые при включении).

### 3.2 Поведение

- `session.start`: регистрация команды `/anon` (`$.command.register`); дочистка сирот
  из `anonManifest` (удаляем файлы, чей sessionId ≠ текущей сессии, запись снимаем);
  env `CLAUDE_ANON=1` → `launcherMode`: инкогнито включён с самого старта (внешний
  запускающий профиль, вне объёма этой спеки); в этом режиме `/anon off` отказывается.
- `command.run` (`/anon [on|off]`): переключение `anonOn`; при каждом превращении в «вкл»
  — запись текущей сессии в `anonManifest`. Тосты: `claude anon on — сессия не
  сохранится` / состояние при off.
- `ui.render {component: 'AbovePrompt'}`: при `anonOn` рисуем фиолетовую полосу
  (Box `backgroundColor` truecolor) во всю ширину `e.bodyColumns` с ASCII-маскотом
  (свой, фиолетовый; аналог ✻-клёйда) и текстом:
  `✻ CLAUDE ANON · сессия не сохранится · память не пишется` (второй сегмент —
  заметка режима: `session not saved`, когда инкогнито был с самого старта; `memory unloaded`, когда вырезка
  контекста состоялась; `context loaded before going anon`, когда включён после хода
  с контекстом — см. 3.1). При
  выключенном — ничего. Уступаем место опросам: если `e.hasSurvey`, пропускаем.
- `ui.render {component: 'SessionMode'}`: при `anonOn` добавляем/рисуем лейбл
  `claude anon` фиолетовым в ряду режимов футера.
- `tool.call` (Write, Edit): при `anonOn` и пути внутри каталога памяти
  (`<CFG>/projects/<sanitized-git-root>/memory/`) → `{ deny: 'claude anon: запись в память отключена' }`.
  Остальные вызовы — `next(e)`.
- `prompt.compose`: при `anonOn` срезаем секции памяти `memory` и `pronouns`, затем
  добавляем последнюю секцию (`scope: 'session'`): правила режима (не писать память,
  не персонализировать, не ссылаться на память).
- `prompt.context` (первый ход беседы, кэшируется движком до compaction//clear):
  при `anonOn` вырезаем блоки `claudeMd`, `userEmail`, `attachedProject`, `gitStatus`
  (`currentDate` и чужие плагиновые остаются), `instructionFiles` отдаём пустыми;
  ставим `contextUnloaded` = true. Ход, случившийся до включения, вырезки не получает
  и state не ставит.
- `prompt.attachment` (per-turn, матчер по `type`): при `anonOn` глушим вложения
  типов `relevant_memories`, `nested_memory`, `current_session_memory`, `team_context` —
  каждый отвечает `{ text: null }` (не уходит).
- `session.end`: при наличии текущей сессии в `anonManifest` удаляем transcript
  и каталог сессии (пути — абсолютные, снятые при включении в запись), плюс побочные
  файлы профиля, помеченные sessionId: строки с `"sessionId":"<id>"` вырезаются из
  `<CFG>/history.jsonl`, удаляются `<CFG>/todos/<id>.json`/`<id>-agent-*.json` и
  каталог `<CFG>/file-history/<id>/`. Всё отсутствующее проходит тихо; файл истории
  без своих строк не переписывается. Неудача любого шага (контейн-мены
  `<CFG>/projects`, todo-каталогов, file-history и history) оставляет запись —
  дочистка на следующем `session.start`. Запись снимаем при успехе; событие
  срабатывает и по signal. Заголовок окна возвращаем (терминал).
- Терминальный заголовок: прямого API нет. При включении/выключении мод спавнит через
  `$.process` без консольного мусора `powershell -NoProfile -Command
  "$Host.UI.RawUI.WindowTitle='Claude Code Anon'"` (SetConsoleTitle меняет заголовок
  общей консоли/вкладки WT); при восстановлении — сперва читаем прежний тем же приёмом.
  Только `e.surface === 'terminal'`.
- Палитра (константы мода, подгоняются при реализации): ANON_BG `#4b2e83`,
  ANON_FG `#f2ecff`, ANON_ACCENT `#b98cff`, ANON_MASKOT `#9b6bff`.

### 3.3 Семантика off (утверждаемая по умолчанию)

Сессия, в которой `/anon` хоть раз включали, **не сохраняется даже после `/anon off`** —
уже попавшее в transcript не «раз-инкогнитить». `/anon off` выключает только полосу,
лейбл и блокировки на будущее. Это правило озвучивается тостом при off.

## 4. Вне объёма

- Перекраска нативной рамки поля ввода и нативного маскота (Clawd) — ядерные элементы,
  мод-API на них нет; полоса примыкает сверху, маскот рисуем свой.
- Полноценное отдельное приложение (TUI на Agent SDK) — отклонено пользователем.
- Замена текста нативного индикатора permission mode (`bypass permissions on` и т.п.) —
  ядерный; наш лейбл идёт рядом с ним.

## 5. Известные ограничения и дыры

1. **Bash-обход записи памяти**: deny-hook закрывает Write/Edit;
   Bash-запись (echo >>) остаётся теоретически возможной — закрывается инструкцией
   `prompt.compose`. Полностью на мод-уровне это не лечится — документируем
   (фоновый сервис extractMemories пишет через Write → его записи deny-hook ловит).
2. **Хард-килл**: `session.end` не гарантирован → сироты дочищиваются при следующем
   `session.start` по `anonManifest` (за этот риск отвечает сам мод); чистка
   побочных файлов сидит в той же записи — ретрируется тем же сиротам-сёрчем.
3. **Контекст до compaction**: вырезка prompt.context применяется к составу
   первого хода; после compaction движок пересобирает контекст заново — вырезка
   ложится снова, но между compaction и пересборкой ход может пройти с прежним
   составом. Смягчение — заглушки памятных вложений per-turn работают каждый ход.
4. **Заголовок вкладки**: если клиент сам перезаписывает заголовок во время работы,
   наш заголовок мог бы перебиваться; мод не переспамливает по таймеру (YAGNI) —
   восстанавливаем на toggle и session.start, при наблюдаемой борьбе пересмотрим.
5. `CLAUDE_BRAND` — форк-специфика (ОКонфиг), на стоке тихо игнорируется.
6. **Статистика и логи не чистятся** (решение пользователя 2026-10-08): чистка
   ограничена побочными файлами сессий — `history.jsonl` (по sessionId), `todos/`,
   `file-history/`; `stats/`, `logs/` остаются намеренно.

## 6. Тестирование

- `claude plugin validate <mod folder>`, `tsc -p` (после первой загрузки движок
  выписывает типы), `claude plugin test <mod folder>`.
- Автотесты мода: toggle-логика `/anon` и состояние; deny-правило Write/Edit по
  путям памяти; манифест-очистка сирот (удаление чужих сессий, нетронутая текущая);
  band рисуется при on и пуст при off; hasSurvey уступает; чистый контекст
  (2026-10-08): вырезка блоков первого хода при on (currentDate остаётся), pass-through
  и честность state до/после включения и на off; заглушки памятных вложений
  (text: null) и проход чужих; срез секций memory/pronouns с последующей политикой;
  чистка побочных файлов (history-строки по sessionId, todos-файлы, file-history
  каталог), отсутствие побочных файлов не ошибка, файл истории без своих строк не
  переписывается.
- Смоук вручную: `/anon on` → полоса+лейбл+тост, Write в MEMORY.md отказан; `/exit` →
  jsonl-файл сессии отсутствует, строки сессии сняты из `history.jsonl`, todos-файл
  и `file-history/<id>/` не остались; `/anon` до первого сообщения → ход без
  MEMORY.md/CLAUDE.md-строк; `/anon` в середине беседы → полоса «context loaded
  before going anon».
